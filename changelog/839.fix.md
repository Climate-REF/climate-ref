Stores non-finite floats as null in JSON columns, so a metric series containing NaN can be ingested on PostgreSQL.

`json.dumps` writes the bare tokens `NaN`, `Infinity` and `-Infinity` by default.
Python reads them back and SQLite stores them without complaint,
but PostgreSQL validates the value on insert and rejects the whole row.
The execution then ended up with 0 metric values and 0 outputs
despite the diagnostic having succeeded and written a complete bundle,
and because the group was left dirty every later solve retried it and failed the same way.

- The sanitising happens on the column type,
  so every JSON write goes through it rather than the one path that was reported.
- Mapping to null keeps the series the same length, which is what a consumer plotting it needs.
- The column DDL is unchanged, so no migration is required.
- `SeriesIndex.compute_hash` is deliberately left alone
  because the series-index migration backfill relies on its serialisation staying stable.
  Two axes differing only in NaN versus None stay separate rows that store the same values.
