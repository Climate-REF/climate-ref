Fixed `ilamb/mrsos-wangmao`, `ilamb/snc-esacci` and `ilamb/amoc-rapid`, none of which could
complete over the full CMIP6 archive.

`ilamb3` is now required at `>=2026.6.15`. Earlier versions derived time measures by casting the
time difference with `astype(float) * 1e-9`, which is only correct for `timedelta64[ns]`; `cftime`
differences (any non-standard calendar, such as the `noleap` WangMao and ESA-CCI references) cast
to microseconds instead, so the reference time step came out 1000x too small. The resulting
`dt_ref=0.0 vs dt_com=30.4` mismatch aborted every `mrsos-wangmao` execution and some
`snc-esacci` ones. Upstream now uses `.dt.total_seconds()`, which is calendar-agnostic.

That upgrade drops the `xarray<2025.11` and `scipy<1.16` pins, both of which existed only to work
around `ilamb3` issues that the new release resolves. Only the ILAMB provider and the framework
itself are affected: ESMValTool and PMP run in their own conda environments.

`amoc-rapid` additionally needed a `climate_ref_msftmz_to_rapid` transform. ILAMB's
`msftmz_to_rapid` selects the Atlantic with a hardcoded `isel(basin=0)`, but the `RAPID-2023-1a`
obs4REF file this provider was moved onto ships the array already reduced to the RAPID section and
has no `basin` dimension, so the selection raised
`ValueError: Dimensions {'basin'} do not exist`.
