Encodes Celery tasks and results as JSON instead of pickle.

Pickle let anything that could write to the broker run arbitrary code in a worker.
The wire format is now JSON, and `pickle` is no longer in `accept_content`.
A rolling deploy with pickled messages still in flight
can set `CELERY_ACCEPT_CONTENT` to include `pickle` until the queues drain.

- The diagnostic no longer crosses the wire.
  Only its slug travels, and the receiver resolves it against its own provider registry,
  importing just the provider named in the slug.
- This fixes a latent bug where the client's conda prefix and `HOME`
  travelled inside the pickled diagnostic and overrode whatever the worker had configured.
- `CondaDiagnosticProvider` no longer snapshots `os.environ` as instance state.
  It keeps only its own overrides and merges the live process environment when a command is launched,
  so settings applied to a worker reach every execution.
- `ExecutionDefinition.diagnostic` is now resolved lazily,
  so the worker handling results never imports a provider at all.
- Non-finite floats are encoded explicitly rather than written as the bare `NaN` and `Infinity`
  literals that `json.dumps` emits by default, which are not JSON and which Postgres rejects.
  This is the same bug class as #839, on a different code path.
  NaN becomes null because it is a missing marker everywhere it appears here,
  while an infinity is a real value and is tagged.
  The encoder also passes `allow_nan=False`
  so anything missed fails loudly instead of producing an unparseable message.
- Messages are also about 40% smaller than the equivalent pickle before compression.
