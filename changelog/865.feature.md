Added `ref doctor`, which checks a deployment for the problems that a solve hides rather than reports:
reference data that is missing (so its diagnostics silently never run),
data ingested under a source type no diagnostic requires (so nothing selects it),
datasets whose files cover the same period twice,
and reference collections that overlap.
It exits non-zero on errors, or on warnings with `--strict`.

`ref doctor --format markdown` (or `json`) additionally reports the versions, configuration, paths, providers and ingested data of the deployment, with credentials redacted, so a report can be pasted into an issue.
Checks are declared with `@check` and listed by `ref doctor --list`; a package outside `climate_ref` contributes its own through the `climate-ref.doctor-checks` entry point group.

Added a generated [Reference data](reference-data.md) page listing every observational dataset the diagnostics require and which collection supplies it.
The page and `ref doctor` are built from the same function, so they cannot disagree.
