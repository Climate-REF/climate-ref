obs4MIPs and obs4REF `instance_id`s are now the identifiers ESGF publishes the datasets under:
the duplicated collection prefix and the `nominal_resolution` segment have been dropped, so
`obs4MIPs.obs4MIPs.NASA-LaRC.CERES-EBAF-4-2-1.mon.rsutcs.100km.gn.v20260220` becomes
`obs4MIPs.NASA-LaRC.CERES-EBAF-4-2-1.mon.rsutcs.gn.v20260220` and
`obs4REF.obs4REF.MOHC.HadISST-1-1.mon.ts.250km.gn.v20250415` becomes
`obs4REF.MOHC.HadISST-1-1.mon.ts.gn.v20250415`.
The collection still leads the identifier, so a file ingested as both obs4MIPs and obs4REF still gets two distinct identifiers.

CMIP6 `instance_id`s name only the primary activity of a dataset that belongs to several, so
`CMIP6.C4MIP CDRMIP.MIROC.[...]` becomes
`CMIP6.C4MIP.MIROC.[...]`, which is the
identifier ESGF publishes it under. The `activity_id` metadata still reports every activity the
dataset belongs to, and an identifier no longer depends on which parser built the catalog.
