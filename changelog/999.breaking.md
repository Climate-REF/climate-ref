Reworked the `climate_ref.results` package to improve the consistency across the readers and filters.

- Removed `ExecutionsReader.statistics`, `select_execution_statistics`, `ExecutionStats` and `DiagnosticsReader.stats`. Use `reader.diagnostics.list`, whose `DiagnosticView.groups` carries the counts.
- `DiagnosticView.slug` is renamed to `diagnostic_slug`, `total` to `execution_count` and `inflight` to `groups.running`. `execution_group_count` and `successful` move to `groups.total` and `groups.successful`.
- `ResourcesReader.profiles` no longer takes `diagnostic_contains`, `provider_contains` or `since`. Pass a `ResourceFilter` instead.
- `ResourceFilter.since` is replaced by `created_after`.
- `ResourceFilter` now keeps only the promoted diagnostic version by default, like the other filters. Pass `include_superseded=True` for every version.
- Removed `MetricValueFilter(promoted_only=...)`, `ExecutionGroupFilter(facets=...)` and the `facet_filters` argument of `get_execution_group_and_latest_filtered`. Use `include_superseded` and `selectors`.
- Moved every results query builder into `climate_ref.results.queries`, so the readers and other callers such as ref-app build the same queries. `select_datasets` is no longer importable from `climate_ref.results.datasets`.
- Added `select_execution_groups` and `select_execution_group_ids`, which take an `ExecutionGroupFilter`. `filter_by_selectors` applies `selectors`, which the database query cannot.
- Removed `get_execution_group_and_latest`, `get_execution_group_and_latest_filtered`, `query_execution_group_and_latest_filtered` and `count_execution_group_and_latest_filtered` from `climate_ref.models.execution`. Use `select_execution_groups` or `ExecutionsReader.group_rows` instead.
- Replaced `latest_execution_for_group(session, id)` with the builder `select_latest_execution(id)`.
- Moved `Reader` into `climate_ref.results.reader`.
- `ExecutionsReader.groups` and `DiagnosticsReader.list` now drop a group whose latest execution is retracted, as `latest_only` already did for values. Pass `include_retracted=True` to keep it.
- `DiagnosticView.groups` now counts only groups at the promoted version by default. Pass `include_superseded=True` for every version.
- `DiagnosticView.execution_count` counts every execution rather than execution groups.
- `ref executions stats` now lists diagnostics with no execution groups, with zero counts.
- `MetricValueFilter(execution_ids=..., latest_only=True)` now keeps the newest of the listed executions, rather than nothing when a newer execution exists.
- `ExecutionScope.created_clauses` is renamed to `execution_clauses`, and now also covers `execution_ids` and `execution_group_ids`.
- Removed `InputDatasetFilter.execution_group_clause` and the `execution_group_where` argument of `select_diagnostics_with_values`. Filter on the `DiagnosticFilter` instead.
- Moved `select_latest_execution` into `climate_ref.models.execution`, beside `select_latest_executions`. It is still importable from `climate_ref.results.queries`.
- `InputDatasetFilter.or_no_model_input` moved to the filters themselves, next to the new `source_types`.
