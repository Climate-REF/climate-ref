Reworked the `climate_ref.results` filters so a field means the same thing, with the same default, on every reader.

- Removed `ExecutionsReader.statistics`, `DiagnosticsReader.stats`, `ExecutionStats` and `select_execution_statistics`. Use `reader.diagnostics.list`, whose `DiagnosticView.groups` carries the per-diagnostic counts.
- Renamed `DiagnosticView.slug` to `diagnostic_slug` and `total` to `execution_count`. `execution_group_count`, `successful` and `inflight` moved to `groups.total`, `groups.successful` and `groups.running`.
- Renamed `ResourceProfile.n_samples`, `n_excluded` and `n_failed` to `sample_count`, `excluded_execution_count` and `failed_execution_count`, and the matching `ref executions resources` columns.
- `diagnostic_slug` and `provider_slug` on the filters are now tuples. They still take one slug, and now also take a list. `isolate_ids` and `exclude_ids` are now tuples too.
- A filter field that takes ids now rejects a string such as `"12"`, and `source_types` rejects an unknown type, rather than matching nothing.
- Removed `InputDatasetFilter.source_types`. Facets are looked up on every dataset type that has them, or only on the reader filter's own `source_types` when it is set. `InputDatasetFilter` now needs `facets` or `dataset_ids`.
- `ResourcesReader.profiles` now takes a `ResourceFilter`, and `ResourceFilter.since` is now `created_after`.
- Removed `MetricValueFilter(promoted_only=...)` and `ExecutionGroupFilter(facets=...)`. Use `include_superseded` and `selectors`.
- Every filter now keeps only the promoted diagnostic version and drops groups whose latest execution is retracted by default. Pass `include_superseded=True` or `include_retracted=True` to keep them.
- Moved the query builders into `climate_ref.results.queries`. Removed `latest_execution_for_group` and the `get_execution_group_and_latest*` helpers in `climate_ref.models.execution`. Use `select_latest_execution`, `select_execution_groups` or `ExecutionsReader.group_rows` instead.
- `ResourceProfile` fields now match `ResourceSummary`: `peak_memory_p50`, `peak_memory_p95`, `peak_memory_max` and `wall_p95` are now `peak_memory_bytes_p50`, `peak_memory_bytes_p95`, `peak_memory_bytes_max` and `wall_seconds_p95`, in Python and in `ref executions resources --format json`.
- `select_scalar_values`, `select_series_values` and `select_value_ids` take `filters` instead of `f`, like the other builders.
- An empty list in `diagnostic_contains`, `provider_contains` or `failure_reasons` now matches nothing, like every other list field. `exclude_ids=[]` still drops nothing.
- A negative `offset` or `limit` now raises `ValueError`, and the CLI rejects a negative `--limit` or `--offset`.
- `execution_group_ids` no longer drops groups that have never run.
- `latest_successful=True` now drops groups with no successful execution, and skips a retracted success unless `include_retracted` is set.
- An unknown `selectors` key, or `--filter` key in the CLI, now raises an error instead of matching nothing. So does an unknown dimension in `OutlierPolicy.group_by`.
- `dimensions={"kind": "model"}` now also matches values with no `kind`, which already read as `"model"`.
- `ref executions inspect` names its argument `GROUP_ID`, shows whether the newest execution is retracted, and warns rather than errors for a group that has not run.
